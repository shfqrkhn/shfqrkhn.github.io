# Prompt Clipboard

Standalone payload: paste a block, or name it and attach the sources. Blocks that cite FileGen or GrandmaTest need those blocks pasted or named with them. The Converge blocks also need the latest Omni, and ConvergeLibrary also needs ConvergeWork. Where a file system and Python are available, the Converge blocks use two small scripts kept outside the library in `converge`: `scan.py` (hashes, relation index, closure keys, status against the last accepted receipt) and `omni_check.py` (Omni identity and reference checks); where they cannot run, every file counts as UNKNOWN and is reviewed in full (Omni 8.4; opaque artifacts by identity and integrity only, with the claim capped). All others are independent.

## Create

Output a file, or distil knowledge into one.

```
FileGen: Output only a downloadable file: the complete, revised, self-contained, independent, stand-alone, holistically/synergistically consolidated, DRY, concise document from the entire conversation and all attached sources, with zero regression and no information lost. Name unsupported gaps; fill them only with distinguishable, authorized, adequately sourced additions; invent no source facts. Meets GrandmaTest.
```

```
GrandmaTest (a projection of Omni section 10; Omni governs): Every tool or deliverable a person uses passes only if a first-time user of its declared audience (non-technical unless the owner declares another) finishes its main tasks with no instructions beyond what is on the screen or page. Concise and utilitarian: only what the main tasks need, with disclosures that change how a task is used kept visible at the point of use, and other disclosures and the how-to-update kept off the main path; plain words with no unexplained jargon; one obvious next step at each point; order and grouping follow the user's real workflow, most common task first; safe defaults; confirm or undo any risky or destructive action; state, progress and saved status always visible; errors say what happened and what to do next; accessible (current applicable WCAG AA where it governs, else the latest verified WCAG AA, at least 2.2) and a layout that fits the device; each item applies where the deliverable has that feature. Updatable end to end: content (data, user-visible text, sources, dates) and look and feel (theme, layout, styling) each change in one place without breaking the other, and, unless the owner states the deliverable is fixed, a short how-to-update sits inside it (for a prompt, kept outside the pasted text). Test it cold: a fresh agent that did not build it plays a first-time user, working from a task list derived from the owner's raw request plus the declared journeys and not the builder's own test plan alone, writing any browser script from the rendered page alone; the update test (N/A where the owner states the deliverable is fixed) is one realistic content change and, where there is a presentation layer, one presentation change, chosen by someone other than the builder, made on a discarded copy using only the how-to; every stall is a defect to fix and re-test. A skipped run counts as failed for any claim of finished quality and above the lowest delivery classes (PROTOTYPE and STATIC_CHECKED); at those classes, and for deliverables with no delivery class, state "first-time-user standard not tested" beside the claim. Claim only what was tested; an agent run is a proxy, not a human test.
```

KnowledgeDistiller has its own standalone file: `TECH-AINT-KnowledgeDistiller.md`. Paste that file whole; it needs nothing else.

## Plan and continue

Plan the remaining work, or hand over to a fresh chat.

```
GoalPrompt: From the whole conversation and all sources, give the complete, concise, revised plan to finish the whole app development (100%), with ALL next /goal prompt(s) (<4000 chars each), holistically synergistically DRY-consolidated where possible. Write each as a literal /goal line in a code block with its character count; each stands alone and restates open owner decisions and superseded values; add no requirement the sources lack (mark proposals), except that every goal building or changing a tool or deliverable requires it to meet GrandmaTest.
```

```
EscapeHatch: From the whole conversation and all sources, give the revised prompt and all files needed to continue in a brand new chat thread. Assert no ordering between sources unless a source dates it; add no unsourced requirement.
```

## Converge

Check and fix existing work, narrowest to widest.

```
ConvergeOmni: OMNI ASSURED. Run only when the Omni key changed since the last ConvergeOmni receipt, or when asked (Omni 8.7). The Omni key is the sha256 printed by `python converge/omni_check.py <path of the latest TECH-AINT-Omni-v*.md>`; only when a ConvergeOmni run ends ASSURED_CONVERGED, recompute it on the final Omni file after its last edit and store it in `converge/receipts/omni.json` as {"sha256": "..."}; with no such file, run. Fix what omni_check.py flags first. Recursively update yourself, then CONVERGE OMNI: apply the full material Omni principle set; fix each contradiction with the smallest edit and show the diff; require 3 consecutive fresh same-key zero-change passes. Changed or delivered files meet FileGen (complete, self-contained, nothing lost or invented).
```

```
ConvergeWork: OMNI ASSURED. Adversarially CONVERGE the full material closure of the actual in-scope work target; presume no project. Scripts first for hashes, links, versions and scans (Omni 8.7): from the repository's `converge` directory (`cd converge`) run `python scan.py --root <target folder>`; model reading only for what a script cannot prove. Require 3 consecutive fresh same-key zero-change passes; a pass that leaves a known defect is not zero-change, and an unresolvable conflict is recorded as an open item, its element is excluded from the claim, and the run finishes at the practical peak with the defect disclosed (Omni 8.6 step 5); ask the owner after delivery. Changed or delivered files meet FileGen (complete, self-contained, nothing lost or invented) and GrandmaTest.
```

```
ConvergeLibrary: OMNI ASSURED. **Goal (Y): every file in scope is true to its sources, consistent with every other file, usable alone and no longer than its purpose needs.** On conflict rank correctness and quality, then completeness of unique facts, then effectiveness, then token-efficiency; cut redundancy, never unique facts. Correct material defects only; never manufacture pass counts. Keep files independent: drop historical meta-prose (release deltas, predecessor chains, "deleted/not retained" notes) and needless cross-links; keep identity, integrity pins, binding constraints, "as of" dates. Apply the latest Omni and ConvergeWork without restating them. Scope: the folders named (the Library); none named = the whole library root; no other drives. Files the owner marks as read-only sources: read and cite them, never edit, move, rename or delete them. Folders listed in `converge/private-skip.txt` (local, git-ignored) are never opened, listed or hashed. Every other file is in scope except tool configuration folders (never read stored credentials or sync tokens) and any `archive` folder; large or binary files are hashed by bytes only and opened only on an owner task. Changed or delivered files meet FileGen (complete, self-contained, nothing lost or invented) and GrandmaTest.

**1 Inventory.** Per file: identity, version, status, class (payload, guide, record, source, built artifact, derived copy), role, hash, what it states about other files. Build one relation index (shared facts, names, versions, decisions, interfaces, supersession, citations, dependencies). From the repository root run `cd converge`, then `python scan.py --all --baseline receipts/library.json`, or `python scan.py --all` when that file does not exist (`--all` lists every file per status; add `--full` for a FULL run; always scan the default library root, and restrict review, not the scan, to the folders named, reviewing their neighbours outside them as closure; folders listed in `converge/private-skip.txt` are never read, listed or hashed by this run, so claims that depend on them are capped inline and left to the owner) for the statuses and broken links (hashes, closure keys and the relation index, saved as each item's links, come from a scratch `--save receipts/scratch.json`); compare with the last accepted receipt (only one saved with `--outcome ASSURED_CONVERGED` counts): same closure key = CARRIED (its earlier full review stands), changed, new and neighbouring files are reviewed in full, and every carried file is reviewed again within its refresh window (Omni 8.4); FULL = carry nothing; no baseline = UNKNOWN, not unchanged. Archives prove history, not authority.

**2 Per-file pass (EVERY file not CARRIED, which includes every file due a refresh; never sample), in the context of all others.** Read fully in bounded portions (opaque artifacts: identity and integrity only; cap the claim). Check purpose, facts against primary sources, chronology, names, paths, versions, omissions, stale volatile claims, privacy, rights, authority, and what the file and others say about each other. *Standalone test:* can a qualified reader use it alone? Scan for terms and acronyms the file never defines. Close each missing definition, assumption, prerequisite or dependency with minimal labelled sourced text, or a one-line pointer where the class allows (payloads restate; guides may link). *Concise test:* cut or point away text duplicating a controlling home (where the class allows) and dead, stale or self-contradicting text; keep every unique fact, rule, source, caveat and provenance.

**3 Cross-file pass.** For each fact, rule, name or version in 2+ files: name the controlling home (one rule, one home), compare copies, quote both sides of each contradiction, resolve by the controlling source (never average). Flag duplication with no distinct purpose; do not merge distinct purposes or promote drafts. Check citations both ways: the target exists and says what the citer says.

**4 Fix and verify.** One batch per round, evidenced net-positive defects only, governing layer first (catalogue, framework, library rules; Omni only through ConvergeOmni), then content; smallest controlling cause first, siblings checked; cascade pins once; recompute a stale pin from the cited file, or remove it if the file is absent. Before replacing a file archive its bytes, verify the hash, keep a tested rollback, promote one file at a time and read it back. Never invent a version. A changed file reopens every file citing it. Archive outside the library in the repository's `history` folder; renaming, moving, merging, splitting or deleting a file (per the library's own naming and versioning rules), or bumping a standalone payload's version (except the patch bump a typo fix requires, including its filename change), needs the owner.

**5 Convergence.** Freeze bytes, relations and evaluator, then run fresh, differently routed passes: (a) coverage, file by file against the relation index; (b) adversarial, by descending risk, with counterexamples and a cold-reader standalone and concision test; (c) executed identity and relation checks. Read once with the smallest available model (labelled unqualified where none is qualified, Omni 8.7 step 3), returning per-file verdicts with exact quotes only; run the adversarial and cross-file passes and every disputed verdict at a stronger tier, and verify each defect by quote against the frozen bytes. Pause at a file boundary when usage runs low and resume on the same key, keeping the manifest and verdicts outside the files (Omni 8.7). One round = freeze, passes until one finds a defect (it finishes its traversal), one fix batch (Omni 8.7); a clean round is three zero-change passes. Exit ASSURED_CONVERGED when a round is clean: three zero-change passes and no verified defect left unfixed (a defect that cannot be fixed is listed with `--open` and disclosed at the practical peak, Omni 8.6 step 5). Once a defect is declared unfixable and its element is excluded from the claim (to be passed with `--open` at the final save), later passes do not count it as a finding. After 3 rounds without a clean round, state the cap and open items and report PARTIAL, never ASSURED_CONVERGED (the 3-round cap is the owner's reduction, Omni 8.2 and 7.3). Never label a file BLOCKED; a failed check is a defect.

**ConvergeOmni, only when the Omni key changed since the last ConvergeOmni receipt or on request (Omni 8.7):** challenge the accepted Omni with evidence; report NO_CHANGE or an off-target diff with rationale and tests; do not edit Omni in this run; when the challenge ends NO_CHANGE, store the current key in `receipts/omni.json` as the ConvergeOmni block says. Apply only fixes that remove a verified contradiction in the library files; list every proposal to change Omni, and other proposals, as owner design items (use the ConvergeOmni block to change Omni; never block the exit, never re-litigated). **Course material, if in scope:** keep full learning coverage, provenance, rights, uncertainty, contrary evidence.

**Receipt (off-target):** scope, exclusions, per-file class and verdict, relation index, contradictions resolved, gaps closed, changed/unchanged files, keys, per-file closure key, review status (REVIEWED, CARRIED or REFRESHED) and the run number of its last full review, this run's number since the last FULL run, refresh window, tokens by stage, passes, rollback, capped claims, missing evidence, and the Omni Appendix B.1 and B.8 fields (Evaluator and worker tiers, isolation method and routes, evidence plan, lowest rung, Limits, Invalidated by); deletion disposition per Omni 16.4; outcome ASSURED_CONVERGED (full claim or practical peak, Omni 8.6) or, for an owner-capped or owner-reduced run (fewer passes, checks or rounds than Omni 8.2 requires), PARTIAL (Omni 8.2, 7.3); an evidence-capped run stays ASSURED_CONVERGED at the practical peak with its claim capped inline. Correlated self-tests never prove independent assurance. If a check misses a demonstrated defect, repair the evaluator and reset; if one cannot run, descend the Omni 8.6 ladder and cap the claim inline; if a repair does not converge, deliver the best candidate and disclose the defect. After the run completes, repeat the step 1 command with the same flags plus `--save receipts/library-new.json --outcome <outcome>` (for any unfixed defect or capped claim add `--open "<path relative to the scanned root, with forward slashes>=<defect>"` or `--cap "<path>=<capped claim and lowest rung>"`, attached to the file most affected; the script records the run number since the last FULL run, the last FULL date and each item's last full review in the receipt, adds `--note "<text>"` to its notes, and removes an inherited cap only with `--clear-cap "<path>"` after a fresh full review); copy that file over `receipts/library.json` only when the outcome is ASSURED_CONVERGED and the review covered the whole library, otherwise keep it as `receipts/library-partial-<date>.json` or, for a folder-restricted run, `receipts/library-scoped-<date>.json`, so such a run never replaces the accepted baseline.
```

## Project

Only when a concrete project is in scope.

```
Project-wide instructions (only when a concrete project is in scope):
1. MPES (Markdown): create/update one complete, code-free mission/product/engineering specification in the project docs folder that alone lets a qualified implementer reconstruct the intended product: scope, architecture, interfaces, material requirements, security/privacy/rights/authority, state, tests, validation, operation, recovery, acceptance. Honor higher-priority instructions and verified constraints; an Omni release may add compatible guidance but is not required. Keep it current. Document the product as built; report suspected defects as proposed changes, never silent ones, and keep documents 1 and 2 from disagreeing about behavior. Record the GrandmaTest requirement (usable by a first-time user of the declared audience with no instructions beyond what the screen or page shows; content and look and feel each updatable in one place; the how-to and update test are N/A where the owner states the deliverable is fixed) in the MPES acceptance criteria, and the cold-run result as evidence.
2. Codebase (Markdown): one portable, self-sufficient document in the docs folder with all unique project code, indispensable build inputs and exact reconstruction steps, so a qualified implementer reproduces the project from it alone using only named, publicly obtainable toolchains and dependencies. Verify clean reconstruction and tests. DRY-compress only if exact behavior, needed assets and license obligations survive. Generate it from a conventional repository if one exists; never keep two competing code authorities.
3. Cleanup and archive preparation (when requested and authorized): remove only provably reproducible caches, temporary outputs and duplicates, after proving dependencies, build inputs, licenses, offline/online needs, tests and recovery still hold. Prefer the smallest reliable archive, not the minimum bytes. Retain irreplaceable sources, configuration, rights/evidence, all material operational state, and secrets only in approved protected storage. Verify clean reconstruction, build/tests and operating paths from the archived contents.
```
